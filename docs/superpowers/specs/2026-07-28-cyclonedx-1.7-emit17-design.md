## What changed since the 2026-07-22 design

| 2026-07-22 assumption | Verified reality (2026-07-28) |
|---|---|
| Converter migration (Tasks 1.5–1.9) precedes 1.7 | **Dropped as prerequisite.** Builder-level extraction of crypto relationships from the embedded 1.6 fields gives emit17 everything it needs with zero `internal/cdxprops` changes. Converter migration is re-filed as independent cleanup. |
| `Curve → EllipticCurve` is a field rename | It is an **enum migration**: `ellipticCurve` is a closed 246-value namespaced enum (`secg/secp256r1`); every string the repo emits today is invalid there. Same for `algorithmFamily` (93 values, closed). No wildcard escape exists. |
| 1.7 requires field surgery day one | **Deprecated ≠ removed**: all six deprecated fields remain schema-legal in 1.7 (the whole 1.6 golden retargeted to `specVersion:"1.7"` validates cleanly). We still migrate day one — that is the point of #175 — but schema validation alone cannot gate it; explicit absence assertions must. |
| Registering "1.7" before emit17 exists = panic window | **Moot.** `NewBuilder` validates through `emitterFor` (builder.go:52-56) and returns an error, never a panicking Builder. |
| Validator wiring is open design | **Solved** by PR #181's `schemaSets` pattern; the 1.7 entry is mechanical and the generic tests cover it automatically. |
| `KeyMeta.Size string` | Shipped as `KeyMeta{Bits int; Curve string}`; still has no producer — not needed for day-one emit17. |

## Decisions

1. **Hybrid by field kind, not surgery-vs-migration.**
   - *Relationship-shaped fields* (`SignatureAlgorithmRef`, `SubjectPublicKeyRef`,
     `AlgorithmRef`, `CryptoRefArray`) are promoted to `cbom.Relationship` entries
     **inside `Builder.model()`**, read from the embedded 1.6 fields on the raw
     components and resolved through the same `safeRefs` drop+warn machinery as
     `dependsOn`. Zero IR type changes (the four kinds already exist, unused).
     emit16 is unaffected (it skips non-DependsOn kinds — pinned by test).
   - *Value-shaped fields* (`Curve`, `CertificateExtension`) are handled by
     per-emitter mapping inside `emit17.Emit` on a deep copy.
2. **emit17 builds `relatedCryptographicAssets` exclusively from `BOMModel.Rels`.**
   `RelatedCryptographicAsset.Ref` is a plain `string` — invisible to the
   reflection rewriter forever. Sourcing from Rels (canonical `AssetRef`s,
   resolvable-by-construction) makes dangling 1.7 refs **structurally impossible**
   and fully decouples 1.7 from the pending 1.6 walker-fix decision.
3. **`cipherSuites[].algorithms` (not deprecated, stays embedded) is canonicalized
   by emit17**: keep entries that are already asset refs; else replace with
   `safeRef(entry)` when that resolves; else drop+warn. This clears the six
   dangling suite refs from 1.7 output (their canonical forms all exist as
   components — proven), so the 1.7 golden asserts ref integrity with a **nil
   allowlist**. 1.6 output stays byte-identical; its 7-ref allowlist stays.
4. **Closed-enum policy: total mapping tables, omit on miss, never passthrough.**
   One stray bare `secp256r1` = schema-invalid document, and the fail-closed
   validator will make CI fail — by design.
5. **`ellipticCurve` source-of-truth rule (anti-fabrication), split by source
   field** *(revised after independent review)*. The trust boundary runs
   through FIELDS, not string forms: `curveField17` maps
   `algorithmProperties.curve` (trusted writer: SSH host keys —
   `nistp256/384/521`, `ed25519`; the fabricated hash-derived writer on
   signature-algorithm assets emits bare `secp*r1` there and is unmapped);
   `paramSet17` maps `parameterSetIdentifier` (trusted writers: EC keys'
   `P-224/256/384/521` from real SPKI, AND TLS ECDHE kex facets carrying raw
   observed named groups — bare `secp*r1`, `x25519`/`ecdh_x25519`,
   brainpool — where bare secg strings ARE trusted; the fabricated writer
   only puts digest sizes there); `nameCurve17` maps OID-definitive names
   (`Ed25519` → `other/Ed25519`, covers X.509 Ed25519 assets whose curve
   appears in no field). Deprecated `curve` is never emitted in 1.7.
   Canonical namespace: `secg/*` for short-Weierstrass, `other/Ed25519`,
   `other/Curve25519` for Edwards/Montgomery.
6. **`algorithmFamily`**: exact-name + prefix-rule table, **plus the
   primitive as a disambiguator** *(revised after independent review)*: the
   TLS kex and auth facets share the `RSA-<n>` name, so name alone cannot
   implement "RSA kex→RSAES-PKCS1" — the rule is `RSA-*` +
   `primitive == key-agree` → `RSAES-PKCS1`; `RSA-*` + signature/empty →
   omit (PKCS1-vs-PSS unknowable). Notables: SHAKE→`SHA-3`,
   ChaCha20-Poly1305→`ChaCha20`, HSS-LMS→`LMS`, XMSS-MT→`XMSS`,
   SSH rsa-sha2-*→`RSASSA-PKCS1`, and the PQC cert sig-alg fallback name
   forms (`crypto/algorithm/ml-dsa-*` etc. — x509.go names unknown sig-algs
   by algorithmName, not display name). **Omit** for: HQC (absent from
   enum), bare RSA keys, Unknown, passthrough hashes.
6a. **`relatedCryptographicAssets[].type` is target-aware for protocol
   edges** *(added after independent review)*: `cryptoRefArray`
   historically points at CERTIFICATES; labeling those `"algorithm"` would
   be schema-legal but false. The emitter labels protocol-crypto edges by
   the target asset's type (`certificate` → `"certificate"`, else
   `"algorithm"`); certificate/material edges keep the official-example
   vocabulary (`"algorithm"`, `"publicKey"`).
7. **1.7 enrichment deferred** (needs converter data not present in components):
   `serialNumber`, `fingerprint`, `certificateExtensions`, cipher `mode` —
   follow-up ticket. `certificateState` is **never** emitted (its NIST lifecycle
   enum has no "expired"; asserting `active` at scan time is fabrication).
8. **`RelSubjectPublicKey` quirk carried forward** (targets the algorithm
   component, not the key material — bug-compatible with 1.6; wire `type` is
   still `"publicKey"`). Fixing it needs a converter change → follow-up.
9. **Default stays 1.6.** `internal/service/client.go` hardcodes a 1.6
   content-type independent of config — flipping the default would silently
   mislabel uploads to CZERTAINLY Core. In scope instead: thread the configured
   version into the upload content-type. Config surface needs no CUE change
   (`version` is an open string, default "1.6"); no CLI flag (no precedent).
10. **Vendor pins — tag 1.7.1, commit `b29bae660048e0ad2fbc5f2972927b442ce951c4`:**
    - `bom-1.7.schema.json` sha256 `73308edec3ab2d38bfffd993e96a042b594314143b6971a6e9ed98bbb6bd76ce`
      (vendor from the spec repo — the copy inside cyclonedx-go v0.11.0 is an older snapshot)
    - `cryptography-defs.schema.json` sha256 `027b059a729a06d591bac79a584ef04f83fc32d91a826fdba6ad3c98a10e5b44`
      (draft-07, zero external refs, `$id` http://cyclonedx.org/schema/cryptography-defs.schema.json)
    - spdx/jsf at 1.7.1 are byte-identical to the already-vendored copies.
    - The defs registry is a living document (KMAC removed, yescrypt added within
      a month) — mapping tables are validated against the **vendored pin** by test.
11. **emit17 `JSONSchema`: `https://cyclonedx.org/schema/bom-1.7.schema.json`**
    (https, matching emit16's convention; the `$schema` property is unconstrained).
12. **Mutation safety**: `Asset.Component`'s crypto substructs are pointers;
    emit17 deep-copies (JSON round-trip) before mutating and a test asserts
    `Emit` leaves its input `BOMModel` byte-identical.

## v0.11.0 bump facts (gating)

- Two source-breaking changes (`IKEv2TransformTypes` fields, `Evidence.Identity`)
  plus a new `License.MarshalJSON` error mode — repo uses none; **whole repo
  builds and `TestGolden_1_6` passes byte-identically under v0.11.0** (proven).
- The only failing test after the bump is the deliberate tripwire
  `TestCycloneDXRefFieldInventory` (57 → 68 entries; gains
  `RelatedCryptographicAsset.Ref` — exactly what the net exists to catch).
- v0.10.0 cannot even *validate* 1.7 documents (`SpecVersion.UnmarshalJSON` has
  no "1.7" case) — the bump gates the validation path too.

## Testing (gates)

- 1.6 golden byte-identity after every task (inviolable).
- `TestGolden_1_7`: schema-valid via extended `schemaSets`;
  `assertRefIntegrity(t, &bom17, nil)` (zero tolerance);
  deprecated fields absent (`curve`, `certificateExtension`,
  `signatureAlgorithmRef`, `subjectPublicKeyRef`, `algorithmRef`,
  `cryptoRefArray`); `relatedCryptographicAssets[].type` vocabulary asserted
  (schema has no enum there).
- Mapping tables: every target value validated against the embedded
  cryptography-defs pin (registry drift fails loudly).
- Validator: bogus `ellipticCurve` must be rejected offline (proves the defs
  schema is actually enforced — the false-pass lesson from #179).
- emit17 input-not-mutated test (marshal before/after).
